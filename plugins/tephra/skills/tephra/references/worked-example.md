# 完整实例：一帧电影画面 → 成品

以「漩涡 + 船」为例，走完七步。每一步都有量化依据，不是拍脑袋。

## 1. 叠网格
读出：漩涡椭圆中心 (0.399, 0.685)，船在 (0.746, 0.712)。

## 2. 体检（原始帧）
```
中位亮度 0.377   可分离性 0.404   → 不通过
```
中位亮度 0.377 意味着画面里没有天然虚空，80% 的黑要靠删——删哪儿全是你猜的。

## 3. 前处理
- **P2 去大气梯度**：远处海面比近处亮，`--floor` 怎么调都不对（低了整片海涌进来，高了内壁跟着海一起没）。减一个 σ=40×120 的高斯背景。
- **P4 换轴**：漩涡内壁 0.288 / 周围海面 0.284——**亮度上是同一个值，那根轴上没有解**。局部对比度：内壁 0.37 / 海面 0.18–0.24，差 1.5–2 倍。改用 `tone × (0.18 + 1.35·contrast)`。
- **P3 裁水印**（右下角），不修补。
- 结果：中位亮度 0.042 / 可分离性 0.616，**超过参照组**。

（这张后来还试了 P5 重打光。三关全过，而且做到了滤镜做不到的事：把漏斗内壁的水纹**打**出来，而不只是重新分配已有亮度。）

## 4–5. 列元素 → 判物理 → 写成分区

| 元素 | 判断 | 参数 |
| --- | --- | --- |
| 漩涡本体 | 天然同心结构 | `--swirl 0.399,0.685,-1.0,0.42,0.25,0,0.22`（RATIO 0.25 是拟合泡沫环主轴量出来的 4.03:1） |
| 船 | 被拉向漩涡，是硬物 | `--anchor 0.746,0.712,0.041,0.230,1.0,3,2.2,56,1.7` 冻结＋保留原色 |
| 崖体 | **岩石不动** | 什么都不给。（曾经误加 152° 让岩石往漩涡流，是错的） |
| 空域 | | `--rain` + `--rain-keepout 0.360,0.800,0.460,0.320` 把漩涡和船围出的左下区排除 |

## 6. 渲
```bash
python3 scripts/tephra.py D_relitA.png -o vortex --size 1400 --palette ash \
  --mass 0 --floor 0.28 --coherence 45 --conserve 1.5 --density 1.7 \
  --stroke 22 --curve 0.05 --jitter 0.02 --length-mix 3 --aniso-len 1.5 \
  --fray 1.4 --gap 0.22 --flow 5 --boil 0.35 --trail 1 \
  --swirl 0.399,0.685,-1.0,0.42,0.25,0,0.22 \
  --anchor 0.746,0.712,0.041,0.230,1.0,3,2.2,56,1.7 \
  --rain 7.0 --rain-angle 150 --rain-spread 25 --rain-wild 1.0 --rain-flow 0 \
  --rain-block 1.1 --rain-short 4 --rain-jitter 0.45 \
  --rain-life 0.16 --rain-px-per-sec 0.6 --rain-speed-len 0.5 \
  --rain-keepout 0.360,0.800,0.460,0.320,1.0 \
  --seconds 1.6 --fps 25 --mp4
```

## 7. 验（相位互相关，逐区量位移）
```
远鳍 dx=-7   近鳍 dx=+5   ← 反向 = 真环流，不是整体平移
左端 |v|=0   右端 |v|=0   ← 端部静止 = 透视压缩对了
船   |v|=0                ← 锚定生效
相邻帧雨点存活率 0.200（参照 0.147，目标 0.10–0.25）
循环闭合 |末−首|/相邻帧差 = 1.00
```

## 另一类题材：暗主体 + 亮背景（马）

马是暗的、天是亮的——**按亮度播种画的是天不是马**。这类必须先判极性。
但 `--invert` 有副作用：主体自己的高光会变成 floor 首先删除的对象（实测马头顶被切掉 0.077 画幅高）。
更稳的是 M0.5 P4 的掩膜路子：纹理造区域掩膜 → 掩膜内用源图自身明暗 → 不需要反相。

## 第三类：局部溃散（雕像 / 马，v7）

### 症状与诊断
"加了溃散但看起来还是很完整"——先量，别看。`scripts/m4_erode.py` 按**源图**算出的 ramp
给成品分箱（成品自己的密度分箱是自指的，本项目已在这上面栽过三次）：

| 版本 | 主体最深箱 fill / 基准 | 判读 |
| --- | --- | --- |
| 只调 START 到 0.80 | 0.98 | 等于没开。脚本日志那行 `free 54%` 是**按画布**算的，大半是主体外的空区 |
| 提到 START 0.55 + escape 2.2 | — | 变成满画布均匀灰雾：飞行距离比实测长 10–30 倍 |
| v7 born 引擎 | 0.33 | 单调下降、核裂成 3 块、粗糙度 2.86 |

### 成品命令
```bash
# 雕像：脸留住，后脑往右上崩解
python3 scripts/tephra.py S_src.png -o dp-statue --size 1400 --palette ash \
  --mass 0 --density 3.6 --sparsity 2.4 --floor 0.17 --coherence 25 --stroke 12 \
  --conserve 1.5 --length-mix 3 --aniso-len 1.5 --fray 1.4 --gap 0.22 \
  --curve 0.05 --jitter 0.02 --flow 2 --boil 0.35 --trail 1 \
  --dissolve=-30,0.28,0.40 --dissolve-patch 0.55 --escape 1.6 --turbulence 1.2 \
  --dissolve-near 0.08 --dissolve-min 0.015 --dissolve-tail 0.45 --dissolve-reach 1.1 \
  --dissolve-keepout 0.78,0.52,0.20,0.30 \
  --rain 2.5 --rain-angle=-90 --rain-keepout 0.56,0.80,0.26,0.24,0.9 \
  --seconds 0.8 --fps 25 --mp4

# 马：头颈与抬起的前腿留住，臀与基座往左崩解
python3 scripts/tephra.py H_src.png -o dp-horse --size 1400 --palette ash \
  --mass 0 --invert --density 3.0 --sparsity 2.4 --floor 0.55 --coherence 18 --stroke 10 \
  --conserve 1.5 --length-mix 3 --aniso-len 1.5 --fray 1.4 --gap 0.22 \
  --curve 0.05 --jitter 0.02 --flow 2 --boil 0.35 --trail 1 \
  --dissolve 180,0.55,0.40 --dissolve-patch 0.55 --escape 1.6 --turbulence 1.2 \
  --rain 2.5 --rain-angle 165 --rain-keepout 0.46,0.44,0.26,0.40,0.85 \
  --seconds 0.8 --fps 25 --mp4
```

### 这一轮踩到的四个坑
1. **溃散轴选错会先吃掉脸**。雕像是仰头的，"上"就是眉骨。−90° 看似符合"跟着余烬走"，
   实际把识别特征排在了最前面。沿 DEG 投影算一遍再定：脸 0.036 < 颅顶 0.17 < 后脑 0.275（−30°）才对。
2. **全散 ≠ 更散**。马 START 0.38 时不散的区域只剩 4%，每颗粒子都出走 → 整体平移+糊。
   崩解是**梯度**现象，必须有锚。
3. **`--conserve` 会把侵蚀补回来**。它按 home 密度补亮，而 home 密度原本是按未位移的位置算的。
4. **画幅覆盖会饱和**。fill 到 0.75 以上时，粒子数砍一半也几乎不掉覆盖率——
   想让侵蚀"看得见"，density 要压在饱和线以下（马 3.0 而不是 3.6）。
   另外 `--seconds` 变长会让 life 变长、同时点亮的笔触变多，画面跟着变糊——
   **改了 seconds 就要重调 density**，1.6s 的 3.6 约等于 0.8s 的 4.6。

### 第二个元素要自己的真空
雕像右边那几点余烬是画面里的第二个元素。飞散一放开，灰烬就盖到它们头上，
两者糊成一片——虚实结合恰恰是靠"实的旁边真的空"。
`--dissolve-keepout 0.78,0.52,0.20,0.30` 把灰烬挡在外面（位移拉短，不删粒子，墨量不变）。
验收：椭圆内填充 4.7% vs 环带 14.8%，约 3 倍反差；余烬各自贴着纯黑。
椭圆半径必须逐颗抖动（脚本内置 ±15%），否则会看到一条完美的弧形遮罩边。

### "散得开"不等于"把云调厚"——这次走了一次弯路
要求是"飞散再远一些、面积再大一些"。第一反应是把 `--dissolve-near` 从 0.08 拉到 0.26 S。
结果被指"过于密集"。回去逐箱对照原作剖面才看清错在哪：

| d/S | 参照 | near=0.26 的那版 | |
| --- | --- | --- | --- |
| 0.015（贴断口） | 0.190 | 0.056 | **0.3×，断口不亮了** |
| 0.35 | 0.026 | 0.022 | 差不多 |
| 0.975（远场） | 0.003 | 0.011 | **3.8×，远处全是灰** |
| 断口/远场 | **63:1** | 5:1 | 云被摊平了 |

原作的云是**断口亮、远场几乎空**；"散得开"靠的是少数几颗真的飞远，不是一片灰摊过去。
`--dissolve-near` 控制的是整朵云的厚度，调大它等于加厚全部——所以新增了 `--dissolve-reach`
专管肥尾能到多远（肥尾只带少量粒子，拉远不加厚）。同时 `--dissolve-min` 从 0.05 降到 0.015：
0.05 S 的最小位移把紧贴断口那一圈掏空了，正是断口不亮的直接原因。

改后：断口/远场 26:1，各箱基本落在参照的 0.5–1.2 倍内。

## 自我审批：一条被自己的指标带偏的结论

我说过"原作飞得不远"。**这句是错的**，而且错法和本项目前三次一模一样：自选指标制造了结论。

用的指标是「绕核心质心的径向平均填充率」。翅膀是一个**窄的定向叶**：
d=1 S 处在 ±15° 扇区里可能有 0.10 填充，摊到 360° 平均就剩 0.008——和"什么都没有"无法区分。
**这个指标在物理上看不见翅膀。** 又只测了 样本A 一件（8 件部分溃散里云最小的那件），
把它的剖面当成了法则。

换成看得见结构的量法（样本S 单帧实测）：

| d / S | 填充率 | 相对核 |
| --- | --- | --- |
| 核内 | 0.162 | 1.00 |
| 0–0.1 | 0.050 | 0.31 |
| 0.25–0.5 | 0.018 | 0.11 |
| 0.5–0.9 | 0.017 | 0.10 |
| 0.9–1.6 | 0.020 | 0.12 |
| 1.6–3.0 | 0.050 | 0.31 |

**根本没有衰减尾。** 出核之后是一条 0.017–0.020 的平台，一路铺到画外 3 S 以上。
连通笔画最长 0.35 S（单笔的 10 倍）——材料是**成结构的**，不是尘。
而我那版是 0.066 → 0.004，衰减到零：所以看起来永远是"掉了一块然后没了"。

三处随之改掉的机制：

1. `--dissolve-floor`：按面积均匀撒 → 远场是**平台**不是尾。
2. `--dissolve-strand`：逃逸位移沿流场**走**，不是直线弹射。
3. `--filament N,LEN,BRANCH,WIDTH,GAIN`：**新层**。在溃散前沿播根，顺流场积分 LEN×S，
   逐级分叉，把路径画进 dust 权重里让笔触沿着排队；落在脉络上的笔触不再二次逃逸。
   **散点无论加多少都长不出结构**——脉络必须显式地生成。

### 三个回归，三个不同的病因（不要一起当"太密"处理）
1. **右上角那团不明物体** = 脉络跑进了空天。修法不是调短，是给路径加**附着斜坡**
   （前 20% 不落墨）+ 硬收尾（`(1-u)^1.6`），并用 DIS 门控 FIL：脉络只属于正在离开的材料。
2. **"有束光打下来"** = 同一批脉络在空处只剩单根，一根孤立路径上的笔触排成虚线，就是一道光。
   收尾一改就没了。右上象限填充 4.4% → 0.96%。
3. **耳朵没了** = 两层原因叠在一起：
   - **笔太长**：耳朵的沟槽在 1400 输出下约 10–20px，`--stroke 12` 画不出来（skill 里写过这条，我违反了）。改 6。
   - **底噪同亮**：耳朵中位亮度 0.055，背景烟也是 0.055——**一模一样，任何 `--floor` 都分不开**
     （和漩涡内壁 vs 海面是同一类问题）。局部对比度能分：耳沟 p95 0.091 vs 平滑烟 0.026，差 3.5 倍。
     按 M0.5 P4 做**区域掩膜**（`scripts/p4_mask.py`：局部标准差 → 闭运算 → 填洞 → 平滑，
     余烬因为小而亮而饱和，会被纹理判据误杀，所以单独保下来），然后 `--floor` 就能压到 0.012。

**教训**：主体身上"暗但有细节"的部件（耳、下颌、发丝）常常和背景同亮。
先量该部件与背景的中位亮度差，差 <0.02 就直接上 P4，别再试 floor。

### 断口切在哪：我连续几轮把方向搞反了
需求原话是「**人脸的一部分**破碎」「碎掉的部分变成画面的一部分、延伸并丰富画面」。
我一直在做的是相反的事：把断口放在后脑、用 `--dissolve DEG` 专门**绕开**脸，
理由是「保住识别度」。结果永远是「一个完整的头 + 旁边一点灰」——
被打碎的那部分本来就是延伸画面的材料，全绕开画面就没东西可延伸。
参照 样本A 本来就是「脸左半完整、右半崩解」，穿过脸。

定量做法：把识别地标沿 DEG 轴投影读 t，让 START 落在地标之间。
DEG=0 时耳 0.06 / 眼窝 0.28 / 鼻梁 0.39 / 颊 0.67；取 START 0.20：
耳和眼窝守住，鼻梁半碎，颊和颅顶整个变成向右延伸的脉络。锚区 26.9%，仍满足 ≥25%。

### 最后一块：碎片要被「推」出去
断口位置和碎法对了之后还差一层——碎掉的像素**留在原地**。
正确的模型不是「密度场」也不是「脉络」，而是：**把碎块当雨点，但发射点是碎块自己**，
方向是一个扇形（这里 −35° ± 28°，往右上），角度逐条随机抽、不走平滑场。

`--spray 7000,-35,28,1.8,1.6` + `--rain-spacing 1.9`（让每条轨迹沿途拉开，越远越稀）。
实现上直接复用 M5 的 dash 引擎，只是把 base angle / spread / speed 从标量改成**逐条数组**，
并去掉原来跨条打乱位置的 permutation——喷出来的那条必须从**它自己的断口**出来。

验收（四象限填充率）：左上 0.37% / 右上 11.0% / 左下 4.9% / 右下 20.4%——
料确实集中在右侧并向右上张开，左半保持真空。

### 最重要的一次纠正：人像的碎，是网点被「梳」出去
在  看到原图之前，我一直在纯粒子（`--mass 0`）里
造各种机制：脉络、密度平台、扇形喷射。全都不对。原作是：

- **实体半边** = 平滑的**有序网点版**，有真实中间调和硬边（脸、手、肩清清楚楚），**没有一点笔触尘**。
- **碎的半边** = **同一块网点**被朝 −25° 左右**梳成硬边条纹**，条纹沿途断成薄片、越远越稀。
  放大看，条纹里还留着原来的抖动点阵——它就是原图的网点被拖出去的。
- **背景** = 极少量、很长、孤立的斜虚线（独立雨层），和碎料完全不同的尺度。

所以新增 `--comb ANGLE,LEN[,SPREAD,THIN,WOBBLE]`：在溃散场之后，把 mass 平面沿角度场
逐段回溯采样（**必须 NEAREST**，双线性会把点阵插成连续灰糊——一试就知道），
每段用一个**硬的逐像素抽签**决定存活，概率 `(1-f)^THIN`，于是条纹沿途断成片。
原处按 `(1-R)^0.85` 削掉，**梳走多少原处就少多少**，质量守恒自带。
SPREAD + WOBBLE 给一个平滑角度场，条纹因此是**弯的**、彼此不平行——就是"风吹柳叶"。

两个实现陷阱（都踩了）：
1. `smooth(a, n)` 的第二个参数是**遍数不是 sigma**。写 `int(0.16*W)` = 672 遍，
   在 4200×2362 上要几分钟。本项目第二次栽在同一个坑（第一次是 `--rain-flow` 的 1260px）。
2. 采样 mass 平面用双线性 = 运动模糊。必须 NEAREST。

### 让梳出去的条纹动起来（而且无缝）
每帧重算一次 comb 太慢（32 抽头 × 4.4M × 20 帧）。但原作的碎料本来就是**闪现**不是巡航
（P-4 实测寿命 0.16s），所以正确的粒度是**一个闪现周期一张平面**：
`--seconds / --rain-life` 张，逐帧按 `int(tt*NC)` 取用，薄片每周期沿轨迹前进一格。

**无缝的条件是可以算出来的**：存活抽签在 `_fp` 上的周期是 1/3，
所以一整个循环的总推进量必须**正好等于 1/3**，相位 NC 才会逐字节回到相位 0。
第一版推进量取了 `2·step/Lmax = 0.0625`，×3 = 0.1875 不是整数周期 → 循环接缝处
跳变是其他相位步的 **1.32 倍**。改成 `(_ph/NC)/3` 之后是 **0.99**。

另外两条：
- `--comb-emit`：**不是每个网点都拉丝**。全拉的话线条互相叠满，出来像火焰不像破损。
  按**源点**抽签（不是按输出像素），一条丝才能沿全程保持身份。0.18–0.25。
- 拉走的点在原处直接**清零**（`1-R`，不是 `(1-R)^0.85`），耳朵/后脑的破洞和丝的飞出
  是同一件事，不需要再单独"咬"一口。

### 两个自己发现的回归，两个都是「规整」惹的祸
1. **羽流远端的梳齿横纹**：所有薄片的距离都是抽头间距的整数倍，于是落在 k·step 的同心环上。
   修法是每个像素在回溯前先沿方向随机退一个**亚抽头偏移**（并把这个偏移算进 f）。
   另外相邻源点走的是完全平行、按抖动点阵等距排开的轨道，点阵与方向拍频成**编织状摩尔纹**——
   再加一个 ±0.8 step 的**横向抖动**才干净。
2. **羽流是一整束**：角度场只有一个低频八度，所有丝被同样地弯，出去就是一捆。
   加第二个八度（0.28 倍尺度、0.55 权重）之后分成几股，边飞边分开。

验收：循环接缝 0.99–1.02，逐帧墨量波动 0.4%，羽流横向剖面的谱峰/中位从明显的梳齿降下来。

### 碎片是「块」不是「丝」
上一版每条丝正好一个网点宽——因为拉丝与存活都是**逐点**抽签的，出来是一梳等宽的细丝。
原作的碎料是**不规则的块**。改成**逐团**抽签：把源点坐标按一个 2–7px 的**团尺寸场**量化后再哈希，
一整团网点一起走、一起断，团的大小又随位置变——宽度就自然参差了。
（同一个量化也用在"原处清零"上，否则洞的边缘和飞出的块对不上。）

### 只留主体
`--rain 0` 关掉独立灰烬层；`p4_mask.py` 默认不再保留余烬（要保留加 `--embers`）；
dust 层压到 `--density 0.10 --sparsity 4.0`。主体左侧空域点亮率 **0.043%**，基本纯黑。

### 五个症状，五个不同的机制原因（一次改完）
| 症状 | 原因 | 改动 |
| --- | --- | --- |
| 主体不如以前清晰 | 512 网格 + 一条粗暴的提亮曲线把中间调压平了 | 网格 512→**768**，提亮换成保中间调的 S 曲线，`--mass 1.8` 放宽实体判定 |
| 碎片是「块」不是「像素条」 | 团尺寸在 x/y 上**各向同性**，出来必然是方块 | 在**条纹自己的坐标系**里量化：顺流向 `cs×CLONG`（长），横流向 `cs×CNAR`（窄 1 格） |
| 不够灵动 | 逐帧存活率被我调到 75%（原作 61%），闪得机械 | `CLIVE` 放到 0.80，并把**漂移**与**消亡**彻底分开 |
| 距离不够 | reach 1.0 S | **1.9 S**，冲出画框 |
| 粒子收束不发散 | 单一平滑角度场——每根被同样地弯，越走越并拢 | 新增 `CDIV`：每个团一个角度偏置，且**随距离增长**，扇形自己张开 |
| 雨点变少变假 | 我为了清灰烬把 rain 一并压到 0.9 | 恢复 3.0，保留 keepout 只挡左半 |

`--comb` 现在是 11 个字段：`ANGLE,LEN,SPREAD,THIN,WOBBLE,PER,LIVE,DIV,NARROW,LONG`。

### 四散、扩散、不规则边界
「太规整」有三个独立来源，各修各的：
1. **车道对齐**：条纹坐标系里的团格子在横流向上对齐，整片读成梯子。给每条车道一个
   哈希偏移把格子错开。
2. **同一射程**：每个团走一样远 → 实心楔形 + 干净弧形边。改成**逐团射程**
   （`CRMIN`，最短只有最长的 0.32）再乘一个粗噪声场 `_EDGE`，外边界因此是**啃出来的**。
3. **发散不足**：角度偏置原来随距离线性增长，改成 `sqrt`，一出断口就张开，`CDIV` 提到 52°。

配合「近密远疏」：占空比仍按 `(1-f)^THIN` 衰减，所以右上半侧被填满但密度一路变稀。
`--comb` 现在 12 个字段：`ANGLE,LEN,SPREAD,THIN,WOBBLE,PER,LIVE,DIV,NARROW,LONG,RMIN`。

### 三个回归 / 误改
1. **画幅被我私自改了**：为了逼近参照的 4:3 我把源图裁了。**不该动。** 已还原 16:9 原始画幅。
2. **雨点被 comb 拖坏了**：comb 需要"每帧一张平面"，我图省事把 `--rain-life` 从
   标定值 **0.16s** 改成 0.04 来驱动它——于是雨点从"活 4 帧的短命闪现"变成一帧就没的碎屑，
   整层标定作废。新增 **`--comb-life`** 专管 comb 的相位数，`--rain-life` 是实测常数，不许动。
3. **末端是"丝带"不是"扇形"**：发散角原来按**当前位置**哈希，也就是每一步重新抽——那是
   *游走*不是*扇形*。改成按**这条路径的输出像素**哈希（一条路一个固定偏置）并从第一步就施加，
   射线才真的从断口以不同方向离开。再叠一个随距离增长的随机游走，末端才散成低密度碎点。

`--comb` 13 字段：`ANGLE,LEN,SPREAD,THIN,WOBBLE,PER,LIVE,DIV,NARROW,LONG,RMIN,WALK`。
